# 평가셋

## 관련도 분류 (`classify-labels.jsonl`)

2026년 10~11월에 13개 소스에서 모은 글 81건 중 50건에 사람이 직접 라벨을 달았다. 보류 판정 글은 모두 넣고, 저장 · 버림은 소스가 고르게 섞이도록 뽑았다.

- 라벨: `save`(수집 기준에 맞는 엔지니어링 글), `inbox`(경계라 사람이 판단할 글), `drop`(기준 밖)
- `memo`: 라벨을 고친 이유. 기준을 다듬을 때 참고한다.
- 글 본문은 넣지 않는다(공개 레포 · 저작권). URL로 `ctx collect --out` 결과와 이어 붙여 평가한다.

```bash
uv run ctx collect --days 30 --out /tmp/articles.jsonl
uv run ctx eval-classify eval/classify-labels.jsonl --articles /tmp/articles.jsonl
# 이미 분류한 결과만 채점할 때 (Claude를 다시 부르지 않는다)
uv run ctx eval-classify eval/classify-labels.jsonl --decisions /tmp/classified.jsonl
```

지표:

- **저장 정밀도**: 저장으로 고른 글 중 정답도 저장인 비율. M1 완료 기준은 80% 이상.
- **놓친 글**: 정답이 저장인데 버린 글. 가장 피할 실수라 따로 센다.
- **일치율**: 저장 · 보류 · 버림이 정확히 맞은 비율. 참고용.

## M0 결과 (2026-11-05, Claude Sonnet, 20건씩 묶어 호출)

| 기준 · 경계값 | 일치율 | 저장 정밀도 | 놓친 글 |
|---|---|---|---|
| 처음 기준, 보류 0.4 · 저장 0.7 | 78% | 100% | 2 |
| 바꾼 기준, 보류 0.4 · 저장 0.7 (2회) | 82%, 78% | 100% | 0 |
| **바꾼 기준, 보류 0.3 · 저장 0.6 (현재 기본값)** | **88%** | **100%** | **0** |

- **바꾼 기준**: 검색 · 추천 시스템 엔지니어링(효과 측정, 임베딩 · 모델 통합과 비용, 서빙)을 수집에 넣었다. 학습 데이터 합성 · 개인화 ML 플랫폼 · 결정 사례 없는 동향 글은 경계(`borderline`)로, ML 모델링은 모델 아키텍처 · 비전 · 음성 모델 · 논문 구현으로 좁혔다. 처음 기준은 추천 효과 측정, 파운데이션 모델 통합 글을 버렸다.
- 바꾼 기준에서는 **어긋난 글이 모두 한 칸 차이**다(저장 ↔ 보류, 보류 ↔ 버림). 저장할 글을 버리거나 버릴 글을 저장한 경우는 없다.
- **출력 안정성**: 호출 14회(81건 분류 5회, 평가 3회 × 3)에서 JSON 오류 · 빠진 판정 0건. 같은 입력을 다시 돌리면 일치율이 4%p 안팎으로 흔들린다.
- **한계**: 50건에 맞춘 경계값이다. 수집이 쌓이면 Inbox 피드백으로 평가셋을 늘려 다시 보정한다.

## 수집 (M0)

- 13개 소스 모두 수집 성공. 최근 30일 81건, 약 20초.
- Kakao, NAVER D2는 원문 페이지가 SPA라 본문 API(`body_api`)를 쓴다.
- Medium(Netflix, Airbnb, 무신사)은 간헐적으로 504를 내서 5xx는 최대 3회 시도한다.
- D2 세션 영상 글은 feed에 요약만 있어 1,000자 안팎으로 저장된다(plan 5.3의 `summary_only`).
